# Booking Assistant

Демонстрационная система записи клиентов: веб-интерфейс, API, административный список и Telegram-адаптер с общей бизнес-логикой. Новый пет-проект для технического портфолио; коммерческое внедрение не заявляется. Код создан с помощью ИИ, решения и ограничения описаны ниже.

Работают выбор услуги и времени, подтверждение, просмотр своих записей, отмена и атомарный перенос. Слот защищён ограничением SQLite; повтор запроса не создаёт вторую запись. Внешние сервисы для основной демонстрации не нужны.

## Посмотреть и запустить

Нужны Python 3.12–3.14 и [uv](https://docs.astral.sh/uv/getting-started/installation/). Если uv ещё нет, установите его через Python:

```console
python -m pip install uv==0.13.1
git clone https://github.com/snijar/booking-assistant.git
cd booking-assistant
uv sync --locked --all-groups
uv run python -m booking demo
```

Откройте **http://127.0.0.1:8000**. База и три условные услуги создаются автоматически. Встречи и клиенты не предзаполнены: первая запись создаётся вами через форму. Все цены демонстрационные.

Для **http://127.0.0.1:8000/admin** скопируйте случайный локальный ключ из терминала. Он действует 24 часа. Новый ключ: `uv run python -m booking admin-key`. Общего пароля нет. `Ctrl+C` останавливает сервер; повторный запуск сохраняет записи, а клиентская cookie продолжает работать.

Если порт занят: `uv run python -m booking demo --port 8001`. Команды одинаковы в PowerShell, macOS и Linux. На Windows, где каталог uv не добавлен в PATH, замените `uv` на `python -m uv`.

Публичного backend-деплоя нет. Скриншоты в [docs/screenshots](docs/screenshots) получены из работающего приложения; они не заменяют локальную проверку. Порядок показа — [docs/walkthrough.md](docs/walkthrough.md).

## Что проверить

```console
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest
```

Браузерная проверка всех основных действий и ширин 390 / 768 / 1440 px:

```console
uv run playwright install chromium
uv run python scripts/browser_check.py
```

Скрипт сам запускает временный сервер и отдельную SQLite-базу, затем останавливает сервер. Скриншоты и результат по умолчанию сохраняются во временную папку, путь выводится в терминал. [Принятые решения и проверки](docs/engineering.md).

## Стек и устройство

Python, FastAPI, SQLite, стандартный `sqlite3`, HTTPX, обычные HTML/CSS/JavaScript; pytest, Ruff, mypy и Playwright для проверок. Один менеджер окружения — uv, точные версии и хеши — `uv.lock`. Сборка frontend не нужна. Docker для такого локального запуска не требуется.

```text
Web → FastAPI API ──┐
                   ├→ BookingService → SQLite (транзакции, ограничения)
TelegramAdapter ───┘
```

`booking/service.py` отвечает за правила и изменения записей, `database.py` — за схему и транзакции, `api.py` — за HTTP и сессии, `telegram.py` — за преобразование команд. Интерфейс находится в `booking/static/`.

## Границы первой версии

- Один специалист, все услуги по 60 минут, ежедневно 10:00–18:00, горизонт записи 30 дней. Выходных, произвольной длительности, филиалов, оплат и напоминаний нет.
- Хранение времени — целые секунды UTC; выбор и отображение — `Europe/Moscow`. Запись в прошлое и изменения после начала встречи запрещены.
- Клиент определяется случайной HttpOnly-cookie, действующей 30 дней. Это гостевая сессия без восстановления: удалив cookie, пользователь теряет доступ к своим записям. Нет связывания веб-сессии с Telegram и полноценной учётной записи.
- В административной части доступен просмотр до 500 последних записей и фильтр по дате. Редактирование услуг и отмена чужих записей администратором не реализованы.
- SQLite проверена на локальном диске. PostgreSQL, распределённая работа и сетевой файловый диск не поддерживаются. Высокая нагрузка не заявляется.
- Telegram-адаптер и повторная доставка проверяются локально. Реальный polling реализован, но с Telegram не запускался. Доставка ответов при аварийном перезапуске может повториться; запись остаётся единственной.
- Это локальное демо. Перед работой с реальными клиентами нужны постоянная авторизация, HTTPS, ограничения частоты запросов, политика хранения данных, резервирование, мониторинг и отдельная проверка внешних интеграций.

## Конфигурация и демо-данные

Приложение читает переменные процесса. `.env.example` — справочник; `.env` автоматически не загружается.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOOKING_DB_PATH` | `data/demo.sqlite3` | Файл SQLite |
| `BOOKING_SECURE_COOKIES` | `false` | `true` только при HTTPS |
| `TELEGRAM_BOT_TOKEN` | не задана | Только отдельный явно разрешённый реальный polling |

Сервер запускается на `127.0.0.1`, допустимые Host — localhost и loopback. Автоматических деплоев, платежей, рассылок и вызовов LLM нет. Логи содержат событие, тип маршрута, статус и длительность; тела запросов, cookies и ключи не журналируются.

Безопасный сброс только локальной `./data/demo.sqlite3`, помеченной приложением как демо:

```console
uv run python -m booking reset-demo --confirm-demo-reset
```

Команда удаляет демо-записи и сессии, сохраняет услуги и отказывается сбрасывать произвольный путь или базу без демо-маркера. После сброса перезапустите демо и обновите страницу.

## Telegram без токена

```console
uv run python -m booking telegram-simulate
uv run pytest tests/test_telegram.py
```

Симулятор не отправляет сообщения. Команды адаптера: `/services`, `/slots ГГГГ-ММ-ДД`, `/book consultation ГГГГ-ММ-ДДT10:00:00+03:00`, `/my`, `/cancel ID`, `/move ID ГГГГ-ММ-ДДT11:00:00+03:00`.

Реальный polling запускается отдельно командой `uv run python -m booking telegram-poll --allow-live`, только с переменной `TELEGRAM_BOT_TOKEN` и после осознанного разрешения владельца бота. Он делает внешние запросы и отвечает реальным пользователям. В рамках проверки портфолио этот режим не использовался. Один бот на одну базу; bot token и update не принимаются публичным HTTP API.

## API и безопасность

Схема — http://127.0.0.1:8000/openapi.json. Краткие примеры — [docs/api.md](docs/api.md). Для всех изменяющих запросов нужен `X-Requested-With: booking-assistant`; для операций записи также `Idempotency-Key`. Ключ повтора привязан к пользователю и отпечатку действия. При конфликте возвращается HTTP 409 с понятным кодом ошибки.

Публичная лицензия пока не выбрана: отдельный LICENSE не добавлен. В репозитории нет существующего клиентского кода, приватных исходников других проектов и реальных данных клиентов.
